# اتصال ابری و آزمایش دو حساب

این راهنما مکمل README است. برای اجرای محلی هیچ‌یک از این مراحل لازم نیست. پیاده‌سازی ابری ارائه شده، اما بدون پروژه و اعتبارنامه واقعی، آزمون سرتاسری آن انجام نشده است.

## قبل از اولین دعوت

- یک پروژه Supabase اختصاصی ایجاد کن و `supabase/schema.sql` را در SQL Editor اجرا کن. این فایل برای پروژه جدید در نظر گرفته شده است؛ پیش از اجرا روی پایگاه داده موجود، پشتیبان بگیر و تداخل نام جدول‌ها و سیاست‌ها را بررسی کن.
- دو متغیر عمومی معرفی‌شده در README را وارد و برنامه را دوباره بساز/مستقر کن.
- دامنه اصلی، دامنه آزمایش و `auth/callback**` را به‌درستی در تنظیمات URL تأیید کن.
- ورود ایمیلی و تأیید ایمیل روشن باشند. ایمیل واقعی ارسال و دریافت شود. از دامنه‌ها، کلیدها و پروژه‌هایی که مالکشان نیستی استفاده نکن.
- مخزن `trip-files` باید **خصوصی** بماند. SQL حجم را ۱۰ مگابایت و نوع‌ها را PDF، JPEG، PNG و WebP محدود می‌کند. این محدودیت جای اسکن بدافزار یا بررسی محتوای فایل را نمی‌گیرد.
- فقط مالک و مدیر گروه دعوت و مدیریت اعضا انجام می‌دهند. یک لینک دعوت، مجوز قابل انتقال است؛ لینک مدیر کامل را عمومی منتشر نکن.

## نقش‌ها

| نقش            | ویرایش مجاز                                     |
| -------------- | ----------------------------------------------- |
| بیننده         | فقط دیدن اطلاعات و فایل‌های سفر                 |
| برنامه‌ریز     | فعالیت، چک‌لیست، مکان و حمل‌ونقل                |
| ویرایشگر هزینه | هزینه‌ها و تسویه‌ها                             |
| مدیر کامل      | همه بخش‌ها، مشخصات سفر، اعضا، دعوت‌ها و حذف سفر |

مالک سفر مدیر کامل است و نمی‌توان او را حذف یا تنزل نقش داد. تأیید نقش فقط یک شرط رابط نیست: توابع پایگاه داده بخش‌های مجاز را دوباره بررسی می‌کنند. یک بیننده می‌تواند اطلاعات مالی را ببیند؛ نقش‌ها محدوده **ویرایش** را تعیین می‌کنند، نه پنهان‌سازی بخش‌های مختلف از اعضای یک سفر.

## اتصال نام دستی به حساب واقعی

عضو سفر و حساب کاربری دو مفهوم جدا هستند؛ می‌توان بدون حساب، نام همراه‌ها و هزینه‌هایشان را نگه داشت. برای پیوند دادن یک نام دستی به حساب، مدیر باید ایمیل واقعی آن فرد را قبل از پذیرش دعوت ثبت کند. فرد با همان ایمیل تأییدشده وارد و لینک را می‌پذیرد. در غیر این صورت، عضو تازه ایجاد می‌شود. اتصال خودکار فقط بر اساس مشابهت نام انجام نمی‌شود.

دعوت جدید برای عضو موجود، نقش او را خودکار بالاتر نمی‌برد. تغییر نقش عضو موجود را مدیر از صفحه هم‌سفرها انجام می‌دهد.

## فهرست آزمایش قبل از استفاده جدی

از دو حساب واقعی و دو مرورگر/پروفایل مرورگر جدا استفاده کن. این فهرست **راهنمای آزمایش است، نه ادعای انجام شدن آن**.

- [ ] حساب الف ثبت‌نام می‌کند، ایمیل را در همان مرورگر تأیید و وارد می‌شود. پس از باز کردن دوباره سایت، نشست معتبر حفظ می‌شود.
- [ ] درخواست بازیابی رمز ارسال، لینک در همان مرورگر باز، رمز تغییر و ورود با رمز جدید امتحان می‌شود. لینک منقضی/استفاده‌شده باید پیام خطای فارسی بدهد.
- [ ] الف سفر واقعی تازه‌ای می‌سازد و آن را ابری می‌کند. سفر و یک مدیر مالک در جدول عضویت ساخته می‌شوند. اطلاعات نمونه را به‌عنوان اطلاعات واقعی گروه منتشر نکن.
- [ ] ایمیل ب در نام دستی همراه ثبت می‌شود. الف لینک نقش بیننده می‌سازد. صفحه پیش‌نمایش لینک در حالت بدون ورود فقط خلاصه دعوت را نشان می‌دهد، نه هزینه و فایل‌ها.
- [ ] ب با ایمیل تأییدشده می‌پذیرد؛ به همان عضو متصل می‌شود، عضو تکراری ساخته نمی‌شود و هزینه‌های قبلی آن نفر حفظ می‌شوند.
- [ ] ب اطلاعات را می‌بیند، اما دکمه‌های ویرایش مجاز نیستند. درخواست مستقیم RPC نامجاز هم توسط پایگاه داده رد می‌شود.
- [ ] الف نقش ب را برنامه‌ریز می‌کند. ب برنامه و مکان را تغییر می‌دهد، اما نمی‌تواند هزینه یا عضویت را تغییر دهد.
- [ ] نقش ویرایشگر هزینه برای ب امتحان می‌شود؛ هزینه و تسویه مجاز، تغییر مسیر و اعضا نامجاز است.
- [ ] الف و ب هم‌زمان **دو فعالیت متفاوت** را ویرایش می‌کنند؛ هر دو تغییر باقی می‌ماند.
- [ ] هم‌زمان یک فیلد واحد را متفاوت ویرایش می‌کنند؛ اختلاف به کاربر نمایش داده می‌شود و انتخاب نسخه، آگاهانه است.
- [ ] شبکه ب موقتاً قطع می‌شود. ویرایش محلی در انتظار می‌ماند؛ با بازگشت شبکه، نتیجه و خطاهای احتمالی بررسی می‌شوند. وضعیت «در انتظار» را با ذخیره قطعی ابری اشتباه نگیر.
- [ ] ب فایل مجاز در بخش مجاز بارگذاری می‌کند؛ الف می‌بیند/دانلود می‌کند. کاربر خارج از سفر نمی‌تواند فایل همان مسیر را بخواند یا URL امضاشده بسازد.
- [ ] فایل بزرگ‌تر از ۱۰ مگابایت یا نوع نامجاز رد می‌شود. نقش ویرایشگر هزینه نباید فایل بخش مسیر/بلیط را بنویسد و برعکس.
- [ ] حضور آنلاین ب با باز و بسته شدن صفحه/اتصال تغییر می‌کند. این علامت، اتصال به کانال همین برنامه است، نه اثبات حضور فیزیکی یا ثبت قطعی زمان آخرین فعالیت.
- [ ] دعوت لغو و دوباره باز می‌شود؛ پذیرش آن باید رد شود. دعوت منقضی نیز رد می‌شود.
- [ ] دسترسی ب حذف می‌شود؛ خواندن و نوشتن جدید در API رد می‌شود و هنگام اتصال، سفر از حافظه نمایشی ب کنار می‌رود. کش آفلاین یا فایل دانلودشده را نمی‌توان به‌طور عقب‌گرد از تمام دستگاه‌ها پاک کرد.
- [ ] ب خارج و حساب دیگری در همان مرورگر وارد می‌شود؛ رکوردهای ابری حساب قبلی نباید در حساب جدید بمانند. سفرهای محلی، مستقل و متعلق به دستگاه هستند.
- [ ] پس از هر مرحله، تراز پول و جمع سهم‌ها با داده ذخیره‌شده مطابقت دارد. ثبت تسویه نباید جمع هزینه‌ها را تغییر دهد.

## در صورت مشکل

**لینک تأیید به صفحه اشتباه رفت:** دامنه و Redirect URLs را بررسی کن. Site URL باید نشانی واقعی برنامه باشد. `**` پایانی مسیر callback را برای پارامترهای بازگشت فراموش نکن. پس از تغییر متغیرهای عمومی، Redeploy لازم است.

**تأیید انجام شد ولی نشست ساخته نشد:** همان مرورگر/نشانی درخواست‌کننده را استفاده کن. لینک قدیمی، منقضی یا یک‌بارمصرف را دوباره استفاده نکن. پس از تأیید ایمیل می‌توانی ورود معمولی با رمز را هم امتحان کنی.

**دعوت عضو تکراری ساخت:** ایمیل نام دستی قبل از پیوستن ثبت نشده یا با حساب دعوت‌شونده متفاوت بوده است. پیش از هزینه‌های جدید، مدیر ارتباط عضو و ایمیل را اصلاح کند. اعضای دارای ارجاع مالی را صرفاً برای پاک کردن نام تکراری حذف نکن.

**تغییر روی دستگاه هست، روی دستگاه دیگر نیست:** وضعیت اتصال و خطای همگام‌سازی، SQL/RLS، کانال Realtime و سهمیه پروژه را بررسی کن. قبل از خروج یا حذف داده‌های مرورگر، پشتیبان بگیر.

**پیوست پشتیبان باز نمی‌شود:** JSON باینری فایل را ندارد. پیوست‌های ابری برای اعضای مجاز و پیوست‌های محلی فقط روی دستگاه دارای باینری قابل دریافت‌اند؛ فایل‌ها را جداگانه حفظ کن.

## عملیات و هزینه سرویس

این برنامه کلید مدیریتی در مرورگر ندارد و سرور اختصاصی فایل لازم ندارد. در عوض، عملکرد حساب، ایمیل، Storage و Realtime به پروژه Supabase و سهمیه آن وابسته است. استفاده زیاد از فایل، اعضا و رویدادهای زنده ممکن است از سهمیه رایگان عبور کند. هیچ سهمیه یا قیمت ثابت و همیشگی تضمین نشده است. برای انتشار عمومی، تحویل ایمیل، نسخه پشتیبان پایگاه داده، مانیتور خطا، سیاست حذف داده و آزمایش امنیت مستقل را در محیط واقعی تکمیل کن.
