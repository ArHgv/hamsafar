# گزارش کنترل کیفیت

تاریخ بررسی: **۱۳ اکتبر ۲۰۲۶ / ۲۱ مهر ۱۴۰۵**.

این گزارش مربوط به سورس همراه بسته است. هدف، شفافیت درباره چیزهایی است که واقعاً اجرا شده‌اند؛ وجود کد یا آزمون موک، معادل اتصال موفق به سرویس واقعی نیست.

## نتیجه‌ها

| بررسی                                     | نتیجه                                                  |
| ----------------------------------------- | ------------------------------------------------------ |
| `npm run typecheck`                       | موفق                                                   |
| `npm test`                                | **۶۰ از ۶۰** آزمون موفق، در ۵ فایل                     |
| `npm run build`                           | ساخت انتشار Next.js موفق؛ ۱۶ مسیر تولید شد             |
| Playwright روی سرور انتشار                | **۱۹ از ۱۹** سناریو موفق؛ اجرای نهایی حدود ۵۶ ثانیه    |
| `npm run format:check`                    | موفق                                                   |
| `npm audit` با وابستگی‌های توسعه و اجرا   | در زمان بررسی، **۰ آسیب‌پذیری شناخته‌شده گزارش‌شده**   |
| اسکن خودکار دسترس‌پذیری صفحات اصلی        | بدون مورد serious/critical در تیره و روشن              |
| بررسی جداگانه دو پنجره و تقویم در دو ظاهر | ۶ اسکن؛ هیچ violation گزارش نشد                        |
| فونت واقعی مرورگر                         | فارسی از وزیرمتن محلی؛ لاتین از فونت سیستم، نه وزیرمتن |

صفر بودن گزارش وابستگی‌ها، تضمین امنیت مطلق نیست. آزمون دسترس‌پذیری خودکار هم جای ارزیابی کامل دستی و صفحه‌خوان را نمی‌گیرد.

## پوشش ۶۰ آزمون دامنه و SQL

- تقسیم مساوی با باقی‌مانده، درصد با گرد کردن دقیق، مبلغ دلخواه و تراز پس از تسویه.
- ادغام سه‌طرفه تغییرهای مستقل، حذف موجودیت و اختلاف ویرایش هم‌زمان.
- قرارداد داده، تاریخ، درصد، محدودیت مبلغ، ورودی cache و پشتیبان، پالایش کلیدهای ناشناخته.
- محاسبه مجوز از تغییر واقعی، قفل ارز پس از تراکنش، پاک کردن ارجاع مکان حذف‌شده، صف آخرین revision و پاک‌سازی رکورد ابری پس از قطع دسترسی.
- جلوگیری از بازگشت ورود به دامنه بیرونی یا مسیر چندبارکدگذاری‌شده، callback کد/نشست و جلوگیری از مبادله هم‌زمان تکراری.
- اجرای schema و RPCها در PostgreSQL تعبیه‌شده PGlite، با محیط‌های نمونه auth، storage و realtime؛ دسترسی مالک، بیننده، برنامه‌ریز و ویرایشگر هزینه، حفاظت مالک، دعوت قابل لغو، ایمیل تأییدشده، پیش‌نمایش محدود ناشناس، محدودیت فایل و حضور خصوصی.

**محدودیت:** PGlite رفتار SQL را می‌سنجد، نه سرویس ایمیل، JWT واقعی، Storage API یا WebSocket واقعی Supabase. آزمون‌های callback نیز از کلاینت پروتکلی موک استفاده می‌کنند.

## پوشش ۱۹ سناریوی مرورگر

۱. رابط فارسی/RTL، جست‌وجو و رفتن به سفر.
۲. ساخت سفر دو نفره با تمام ساعت‌ها، بلیط و شماره مسیر خالی؛ حفظ داده بعد از بارگذاری مجدد.
۳. تیک چک‌لیست، افزودن وسیله و پایداری داده.
۴. ثبت تقسیم مساوی، دلخواه و درصدی با جمع دقیق.
۵. جلوگیری از درصدهای نامعتبر و نمایش خطای فارسی.
۶. ثبت تسویه بدون تغییر جمع هزینه‌ها.
۷. افزودن فعالیت و تغییر وضعیت به انجام‌شده/لغوشده.
۸. مدیریت همراه و نمایش صریح محدودیت دعوت محلی.
۹. ذخیره مختصات، انتخاب مکان بدون کلیک اجباری و لینک واقعی مسیر گوگل‌مپ.
۱۰. تغییر به قطار و ثبت شماره قطار/سکو بدون بلیط.
۱۱. نبود overflow افقی در **۱۲ مسیر** با اندازه **۳۷۵ × ۸۱۲**.
۱۲. اسکن WCAG 2 A/AA و 2.1 A/AA با axe روی `/`، `/trips/new`، `/expenses` و `/groups`.
۱۳. ظاهر روشن، ماندگاری انتخاب و کاهش شفافیت، همراه اسکن همان مسیرها.
۱۴. دریافت JSON، حذف سفرهای محلی و بازیابی سه سفر.
۱۵. تایپ تدریجی اعشار و علامت منفی مختصات بدون بازنویسی مخرب مقدار موقت.
۱۶. انتخاب از تقویم خورشیدی و ساعت اختیاری ۲۴ساعته.
۱۷. بازیابی داده خام از localStorage خراب، بدون crash.
۱۸. نگه‌داری و دریافت رسید PDF محلی از IndexedDB بعد از refresh.
۱۹. پیشروی با Enter در دو مرحله، بدون ساخت زودهنگام سفر قبل از مرور نهایی.

تمام سناریوها خطاهای uncaught صفحه را نیز بررسی می‌کنند. رسید آزمایشی، آزمون پایداری باینری است، نه آزمون صحت ساختار محتوای PDF.

## بررسی تکمیلی دستی/ابزاری

- بررسی بصری نمای کلی در رایانه و موبایل، سلسله‌مراتب RTL، سطح‌های آرام، ناوبری شناور موبایل و تصویر کاور.
- اسکن مستقل پنجره ثبت هزینه، پنجره وسیله و تقویم باز در تیره و روشن؛ بدون violation خودکار.
- استفاده از Chrome DevTools Protocol برای فونت‌های رندرشده: متن فارسی وزیرمتن، متن لاتین فونت سیستم Linux در محیط آزمایش. در دستگاه Apple، پشته سیستم Apple/SF انتخاب می‌شود.
- پاسخ HTTP موفق از سرور انتشار، محدودیت دسترسی دوربین/میکروفون و headerهای جلوگیری از sniffing بررسی شد.

## چه چیزهایی هنوز نیازمند محیط واقعی‌اند؟

- ثبت‌نام، ارسال ایمیل، لینک تأیید و بازیابی رمز با حساب واقعی.
- انتشار و پذیرش دعوت بین دو حساب، Storage واقعی، حضور و Realtime در شبکه واقعی.
- کیفیت همگام‌سازی در افت شبکه، تغییر نقش/حذف دسترسی هم‌زمان با ویرایش و مصرف نزدیک سهمیه سرویس.
- تجربه VoiceOver/NVDA، موبایل فیزیکی، صفحه‌کلید نرم و نصب PWA روی iOS/Android.
- شروع کاملاً آفلاین پس از بسته شدن مرورگر در همه مسیرها؛ تضمین نشده است.
- route/ETA واقعی، تبدیل نرخ ارز و پرداخت بانکی؛ در دامنه نسخه فعلی نیستند.
- آزمون نفوذ مستقل، اسکن محتوای فایل، پشتیبان باینری و سیاست نگه‌داری/حذف orphanها.
