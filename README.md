# هم‌سفر

**کمتر برنامه بریز، بیشتر زندگی کن.**

وب‌اپ فارسی و راست‌به‌چپ برای برنامه‌ریزی سفرهای شخصی و گروهی؛ از اولین مقصد تا آخرین تسویه. طراحی تیره و روشن، متریال شیشه‌ای آرام، فونت فارسی وزیرمتن و رابط سازگار با موبایل و رایانه.

> بدون حساب و بدون کلید سرویس هم کار می‌کند. داده‌ها در مرورگر همان دستگاه ذخیره می‌شوند. اتصال اختیاری Supabase، حساب واقعی، دعوت، فضای فایل خصوصی و همکاری بین دستگاه‌ها را فعال می‌کند. این دو حالت در رابط مشخص هستند؛ حضور آنلاین یا لینک دعوت در حالت محلی شبیه‌سازی نمی‌شود.

## چه چیزهایی آماده است؟

- **نمای کلی:** سفرهای جاری، آینده و گذشته، هزینه‌ها به تفکیک ارز، وضعیت کیف سفر و تسویه، دسترسی سریع به گروه‌ها.
- **ساخت سفر سه‌مرحله‌ای:** مقصد، تاریخ خورشیدی، همراه‌ها، بودجه، کاور و جزئیات هوشمند ماشین، هواپیما، قطار، اتوبوس و مسیر ترکیبی. ساعت‌ها، بلیط‌ها و شماره مسیر همگی اختیاری‌اند.
- **برنامه روزانه:** صبح، ظهر، عصر و شب؛ فعالیت، مدت، یادداشت و مکان؛ وضعیت در انتظار، انجام‌شده و لغوشده.
- **کیف سفر:** دسته‌بندی، اولویت، تعداد، وزن اختیاری، مسئول، وسایل مشترک، الگوهای آماده و درصد تکمیل.
- **حساب روشن:** پرداخت‌کننده، رسید، دسته‌بندی، تقسیم مساوی، مبلغ دلخواه یا درصدی، تراز دقیق هر نفر، پیشنهاد انتقال و ثبت تسویه انجام‌شده.
- **نقشه واقعی:** نقشه Leaflet با لایه‌های CARTO/OpenStreetMap، مکان‌های دسته‌بندی‌شده، انتخاب مختصات و باز کردن مسیر در گوگل‌مپ.
- **همراه‌ها:** نقش مدیر کامل، برنامه‌ریز، ویرایشگر هزینه و بیننده؛ حضور در سفر، دعوت قابل لغو و وضعیت آنلاین مبتنی بر اتصال واقعی در حالت ابری.
- **تنظیمات:** ظاهر تیره/روشن/مشکی-طلایی/سفید-طلایی/دستگاه، کاهش شفافیت، پشتیبان JSON و بازیابی، راهنمای نصب روی صفحه اصلی.
- جست‌وجوی سریع با `⌘ K` یا `Ctrl K`، تقویم سفرها، حالت‌های خالی و خطا، اعلان‌های فارسی، حرکت کاهش‌یافته و دسترسی با صفحه‌کلید.

## سریع‌ترین راه امتحان کردن

۱. برنامه را باز کن؛ سه سفر **نمونه** برای آشنایی حاضرند.
۲. از «ساخت سفر» سفر خودت را بساز؛ هیچ ساعت یا بلیطی لازم نیست.
۳. داخل سفر، تب‌های برنامه، کیف سفر، هزینه‌ها، تسویه و مکان‌ها را امتحان کن.
۴. در تنظیمات نام خودت را بنویس. بعد از آشنایی، با «پاک کردن سفرهای محلی» نمونه‌ها را حذف کن.
۵. از تنظیمات، یک نسخه پشتیبان بگیر. پاک کردن داده‌های مرورگر می‌تواند اطلاعات محلی را حذف کند.

**وسایل شخصی** یعنی مسئولیت یک نفر، نه محرمانه بودن در برابر سایر اعضای سفر. تمام اعضای مجاز می‌توانند اطلاعات سفر مشترک را ببینند.

## اجرا روی رایانه؛ چهار قدم

نیازی به Supabase برای شروع نیست.

۱. [Node.js](https://nodejs.org/) نسخه **۲۲ LTS** را نصب کن.
۲. فایل ZIP را باز کن و پوشه `hamsafar` را در ویرایشگر یا ترمینال باز کن.
۳. این دو دستور را داخل همان پوشه اجرا کن:

```bash
npm ci
npm run dev
```

۴. در مرورگر به **http://localhost:3000** برو. ترمینال را باز نگه‌دار؛ برای توقف `Ctrl C` بزن.

برای اجرای نسخه بهینه‌شده به‌جای حالت توسعه:

```bash
npm run build
npm run start
```

اگر پورت ۳۰۰۰ مشغول است:

```bash
npm run dev -- --port 3001
```

## انتشار روی Vercel

۱. یک مخزن جدید بساز و **محتویات پوشه `hamsafar`** را در آن قرار بده. پوشه‌های `node_modules` و `.next` و فایل‌های `.env.local` را بارگذاری نکن.
۲. در [Vercel](https://vercel.com/) گزینه **Add New → Project** را بزن و مخزن را انتخاب کن.
۳. فریم‌ورک **Next.js** را انتخاب کن. تنظیمات پیش‌فرض نصب و ساخت کافی است. نسخه Node را **۲۲** بگذار.
۴. **Deploy** را بزن؛ نسخه محلی آماده استفاده است و هیچ متغیر محیطی لازم ندارد.

اگر پروژه در زیرپوشه مخزن است، در **Root Directory** همان پوشه `hamsafar` را انتخاب کن.

در نسخه محلی، هر مرورگر اطلاعات مستقل دارد؛ داشتن نشانی عمومی به‌تنهایی داده‌های دستگاه‌ها را مشترک نمی‌کند. برای سفر گروهی بین دستگاه‌ها، مرحله بعد را انجام بده.

راهنمای مستقل انتشار و توضیح انتخاب Supabase در برابر Firebase: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

میزبان‌های دیگری هم که Next.js و Node را پشتیبانی کنند قابل استفاده‌اند. این پروژه خروجی ساده HTML برای میزبان‌های کاملاً ایستا نیست. شرایط و سهمیه سرویس‌های رایگان ممکن است تغییر کند؛ پیش از استفاده جدی، محدودیت حساب خودت را بررسی کن.

## فعال کردن حساب و همکاری ابری

راهنمای تصویریِ سرویس‌ها لازم نیست؛ فقط سه کار اصلی داریم: **ساخت پروژه، اجرای SQL، وارد کردن دو مقدار عمومی.**

۱. در [Supabase](https://supabase.com/dashboard) یک پروژه جدید بساز.
۲. فایل `supabase/schema.sql` همین پروژه را باز کن. کل محتوای آن را در **SQL Editor** پروژه Supabase وارد کن و **Run** بزن. فایل، جدول‌ها، نقش‌ها، توابع امن، دعوت‌ها، سیاست‌های دسترسی، انتشار تغییرات و فضای خصوصی `trip-files` را می‌سازد.
۳. از تنظیمات API پروژه، **Project URL** و کلید عمومی **anon** یا **publishable** را کپی کن.
۴. در Vercel، بخش **Settings → Environment Variables**، این دو متغیر را با مقادیر واقعی وارد کن:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

**هرگز** کلید `service_role`، کلید secret یا رمز پایگاه داده را اینجا وارد نکن. این دو متغیر عمومی‌اند؛ حفاظت داده‌ها با سیاست‌های دسترسی پایگاه داده انجام می‌شود.

۵. در Supabase، بخش **Authentication → URL Configuration**:

- **Site URL:** نشانی اصلی برنامه، مثلاً `https://YOUR_APP.vercel.app`
- **Redirect URLs:** نشانی کامل زیر؛ `**` انتهای آن برای پارامترهای بازگشت ورود و بازیابی رمز است:

```text
https://YOUR_APP.vercel.app/auth/callback**
http://localhost:3000/auth/callback**
```

فقط دامنه‌های تحت کنترل خودت را مجاز کن. برای دامنه جدید یا پیش‌نمایش آزمایشی، نشانی همان دامنه را جداگانه اضافه کن؛ همه دامنه‌های Vercel را با یک الگوی عمومی باز نکن.

۶. در تنظیمات ورود ایمیلی، **Confirm email** را روشن نگه‌دار. اتصال همراهِ ازپیش‌ثبت‌شده به حساب واقعی، به مالکیت تأییدشده ایمیل وابسته است. حداقل طول رمز را ۸ یا بیشتر بگذار. برای استفاده عمومی، ارسال‌کننده ایمیل/SMTP خودت و محدودیت ارسال ایمیل سرویس را تنظیم و امتحان کن.
۷. در Vercel، **Redeploy** بزن. متغیرهای `NEXT_PUBLIC_` هنگام ساخت وارد برنامه می‌شوند؛ ذخیره متغیر بدون ساخت مجدد کافی نیست.
۸. حساب بساز و ایمیل را تأیید کن. لینک تأیید و بازیابی رمز را ترجیحاً در **همان مرورگر و همان نشانی سایت** که درخواست داده‌ای باز کن؛ جریان ورود از PKCE استفاده می‌کند.
۹. در صفحه هم‌سفرهای یک سفر، «دعوت» را بزن و سفر محلی را به فضای ابری بفرست. سپس نقش دعوت‌شونده را انتخاب و لینک را کپی کن. لینک‌ها هفت روز اعتبار دارند و قابل لغو هستند.

**نکته همراه‌های ازپیش‌ثبت‌شده:** اگر کسی را قبلاً با نام وارد کرده‌ای، ایمیلِ مورد استفاده او برای ورود را هم در ویرایش آن همراه ثبت کن. در این صورت ورود با همان ایمیل به همان نفر متصل می‌شود؛ بدون ایمیل ممکن است عضو جدیدی کنار نام دستی قبلی ایجاد شود. دعوت، ایمیل خودکار به اعضا ارسال نمی‌کند؛ لینک را خودت برایشان بفرست.

برای اتصال ابری در رایانه خودت، `.env.example` را با نام `.env.local` کپی کن، مقادیر را وارد کن و سرور را دوباره اجرا کن. این فایل را در مخزن عمومی قرار نده.

راهنمای دقیق‌تر و فهرست آزمایش دو حساب واقعی: [docs/CLOUD.md](docs/CLOUD.md).

## چند نکته مهم، بدون ادعاهای اضافی

- **پیش‌نمایش آماده، محلی است.** پیاده‌سازی Supabase، SQL و آزمون‌های آن در سورس وجود دارند؛ اتصال به پروژه واقعی کاربر بدون کلیدهای واقعی آزمایش نشده است.
- **محلی با آفلاین کامل فرق دارد.** صفحه بازشده و داده‌های محلی بدون سرویس ابری کار می‌کنند. PWA فایل‌های رابط و فونت را ذخیره و صفحه جایگزین آفلاین ارائه می‌کند، اما باز شدن همه مسیرها پس از بستن مرورگر در آفلاین تضمین نشده است. نقشه، مسیریابی و همگام‌سازی اینترنت می‌خواهند.
- **پشتیبان JSON شامل باینریِ بلیط و رسید نیست.** کاور و داده‌ها و اطلاعات پیوست‌ها صادر می‌شوند؛ فایل‌های مهم را جداگانه دانلود و نگه‌داری کن. وارد کردن پشتیبان، نسخه محلی می‌سازد و پروژه ابری را بازنویسی نمی‌کند.
- اطلاعات محلی و فایل‌های IndexedDB **رمزگذاری نشده‌اند**. حالت خصوصی مرورگر یا پاک کردن داده‌های سایت ممکن است آن‌ها را حذف کند. روی دستگاه مشترک از حساب ابری خارج شو؛ برای حذف کامل فایل‌های محلی، داده‌های سایت را از تنظیمات مرورگر پاک کن.
- هزینه‌های ارزهای مختلف با هم جمع یا تبدیل نمی‌شوند. تومان و ریال بدون اعشار، دلار و یورو با دو رقم اعشار ذخیره می‌شوند. بعد از ثبت تراکنش، تغییر ارز سفر بسته می‌شود تا معنی مبلغ‌ها عوض نشود.
- تقسیم و تراز با کوچک‌ترین واحد پول محاسبه می‌شود؛ سهم‌های گرد‌شده دقیقاً به مبلغ هزینه می‌رسند. پیشنهاد انتقال، یک ساده‌سازی عملی است، نه تضمین کمترین تعداد انتقال در تمام حالت‌ها. برنامه پرداخت بانکی انجام نمی‌دهد؛ تسویه، ثبت پرداخت انجام‌شده در بیرون برنامه است.
- فاصله‌ها **خط مستقیم** هستند و زمان‌ها برآورد ساده‌اند؛ مسیر واقعی خیابان، ترافیک یا زمان پرواز نیستند. گوگل‌مپ برای مسیریابی واقعی باز می‌شود.
- در قطع دسترسی گروه یا خروج از حساب، رکوردهای ابری از نمای محلی کنار می‌روند. قبل از خروج، مطمئن شو تغییرات در انتظار همگام شده‌اند یا پشتیبان گرفته‌ای. فایل‌های محلی مستقل ممکن است همچنان در حافظه مرورگر بمانند.

## برای توسعه‌دهنده

**پشته:** Next.js 15 / React 19 / TypeScript، Tailwind CSS 4 و CSS variables، Framer Motion، Radix، React Hook Form / Zod، Zustand، Supabase و Leaflet.

```text
app/                 مسیرها، چیدمان RTL، خطا و بارگذاری
components/
  ui/                کنترل‌های مشترک، پنجره، تقویم، ورودی عددی، پیوست
  layout/            پوسته واکنش‌گرا، ناوبری، جست‌وجو و تقویم کلی
  dashboard/         نمای کلی
  trips/             کارت، فهرست، ساخت و جزئیات سفر
  features/          برنامه، کیف سفر، هزینه، تسویه، نقشه، گروه و حمل‌ونقل
hooks/               انتخاب سفر، هویت و مجوز
lib/                 مدل، اعتبارسنجی، پول، تاریخ، ادغام، فایل و سرویس ابری
store/               وضعیت پایدار و وضعیت رابط
supabase/schema.sql  پایگاه داده، دسترسی‌ها و توابع تراکنشی
public/              کاور، فونت، آیکون و فایل‌های PWA
tests/               آزمون‌های دامنه، پول، ادغام، ورود، SQL و مرورگر
docs/                راهنمای ابری، معماری و گزارش کنترل کیفیت
```

```bash
npm run check          # TypeScript و آزمون‌های واحد/SQL
npm run build          # ساخت نسخه انتشار
npx playwright install chromium
npm run test:e2e       # آزمون واقعی مرورگر
npm run format:check   # یکدستی قالب کد
```

آزمون مرورگر در محیط توسعه، سرور را در صورت نیاز بالا می‌آورد؛ در CI، پس از ساخت از سرور انتشار استفاده می‌کند. اگر سرور انتشار را قبلاً روی پورت ۳۰۰۰ اجرا کرده باشی، آزمون از همان استفاده می‌کند. در لینوکس ممکن است `npx playwright install --with-deps chromium` لازم باشد.

جزئیات تصمیم‌های مدل و رشد پروژه: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). نتیجه آزمون‌ها و محدودیت شواهد: [docs/QA.md](docs/QA.md).
